# مرحلہ صفر — محفوظ بنیاد اور تعیناتی کی شناخت

تاریخ: ۲۸ اگست ۲۰۲۶، پاکستانی وقت۔ حالت: **مقامی کام مکمل؛ مرحلہ اول کی اجازت درکار ہے۔**

اس مرحلے میں مالی حساب، پی ٹو پی، لوکیشن، صارف اجازتوں، فائر بیس قواعد یا زندہ معلومات کی منطق نہیں بدلی گئی۔ نہ تعیناتی ہوئی، نہ نئی ادائیگی والی خدمت فعال ہوئی، نہ Git کی اصل شاخ/محفوظ تبدیلیاں بدلی گئیں۔

## کیا درست کیا گیا

1. اصل کام اور موجودہ تیار ویب پیکج کی مقامی محفوظ نقل، ہر فائل کی جدا شناخت اور مجموعی شناخت شامل کی گئی۔
2. نقل کی جانچ اور نئی خالی جگہ میں واپسی کا آلہ بنایا گیا۔ یہ اصل جگہ پر فائلیں نہیں چڑھاتا اور موجودہ ہدف کو بدلنے سے انکار کرتا ہے۔
3. تعیناتی سے پہلے پہرہ اب صرف ترتیبات نہیں، چاروں ایپس، مشترکہ کوڈ، قانونی/جامد فائلیں اور تعمیر کے متعلقہ اوزار بھی دیکھتا ہے۔
4. نظرانداز یا غیر محفوظ اضافی فائل بھی تعیناتی کو روک سکتی ہے۔ فائلوں کے مواد کا فرق چھاپنے کے بجائے صرف نام دکھائے جاتے ہیں۔
5. ویب پیکج کی مہر میں محفوظ کوڈ شناخت کے ساتھ **اصل موجودہ فائلوں کی شناخت، تیار پیکج کی شناخت، فائلوں کی تعداد اور غیر محفوظ تبدیلی کی حالت** شامل ہے۔
6. تعمیر کے دوران اصل فائل بدل جائے، تعمیر کے بعد تیار فائل بدلے یا پہلے کی مہر/پہرہ غائب ہو تو تصدیق ناکام ہوتی ہے۔
7. ویب پیکج بنانا اب سرور کی خودکار گاڑی فہرست کو نہیں لکھتا؛ اس کا الگ واضح حکم موجود ہے۔ پہلے سے بدلی ہوئی سروری فائل محفوظ رہی۔
8. بنیادی ویب جانچ میں مالک کا حصہ بھی شامل کیا گیا، ہر درخواست کو وقت کی حد دی گئی اور پڑھی گئی عوامی فائلوں کی شناخت محفوظ ہوتی ہے۔
9. اگلے مراحل اور تمام ۶۴ معائنہ نکات [مستقل منصوبے](ROADMAP.md) میں الگ شناخت کے ساتھ محفوظ کیے گئے ہیں۔

## معلوماتی ساخت کی بنیاد

اصل قواعد، اشاریے، سروری کوڈ اور ترتیب مکمل مقامی نقل میں محفوظ ہیں۔ اگلی مالی/اختیاراتی اصلاح کے لیے متعلقہ مجموعے یہ ہیں:

- شناخت/اختیار: `users`, `partners`, `drivers`, `admin_registry`, `settings`, `driver_applications`, `owner_applications`۔
- سواری/گاڑی: `rides`, `vehicles`, `ride_offers`, `ride_candidates`, `booking_slots`, `vehicle_pins`, `pin_attempts`۔
- لوکیشن: `rideViewerPresence`, `ridePeerSessions`, `rideBreadcrumbTelemetry`, `rideLocationReports`۔
- مالی/نگرانی: `ledger_transactions`, `rechargeRequests`, `promoCodes`, `audit_logs`, `ops_metrics`۔
- اعتماد/پرانے راستے: `account_deletion_requests`, `support_reports`, `bookings`, `ride_requests`۔

موجودہ ترتیب میں اصل منصوبہ `swiftgo-ride-app`، ویب ڈائریکٹری `hosting-dist` اور سرور کا مطلوبہ چلانے والا نسخہ `nodejs22` ہے۔ مقامی اوزار `v24.16.0` پر آزمائے گئے ہیں؛ اس مرحلے میں سرور کے نسخے یا منصوبے کے عرف تبدیل نہیں ہوئے۔

یہ **ساخت کی مقامی بنیاد** ہے، زندہ معلوماتی مرکز کی موجودہ معلومات، قواعد کے تعینات نسخے یا معلوماتی خطے کی تصدیق نہیں۔

## دوبارہ استعمال کے احکامات

نئی مقامی نقل:

```powershell
npm run baseline:capture -- before-phase-one
```

موجودہ نقل کی تصدیق:

```powershell
npm run baseline:verify -- .release-baselines/2026-08-28T01-03-36-350Z-before-remediation-f0e548
```

واپسی ہمیشہ نئی جگہ میں ہوگی؛ نیچے کا ہدف پہلے سے موجود ہو تو حکم رک جائے گا:

```powershell
npm run baseline:restore -- .release-baselines/2026-08-28T01-03-36-350Z-before-remediation-f0e548 .release-baselines/recovery-next
```

نئی جانچ:

```powershell
npm run test:phase-zero
```

واپس بننے والی `source` ڈائریکٹری کا جائزہ لے کر، اگلی واضح اجازت کے بعد منتخب تبدیلیاں اصل کام میں منتقل کی جائیں۔ محفوظ نقطے پر خودکار `git reset` نہ کریں؛ اس سے پہلے کی غیر محفوظ محنت ضائع ہوسکتی ہے۔ سرور، قواعد اور مالی معلومات کی واپسی اس آلے کا کام نہیں۔

## باقی حدود

- یہ اسی مشین کی مقامی نقل ہے، دوسری جگہ آفت سے محفوظ نقل نہیں۔ Git تاریخ، مرحلہ وار محفوظ index، نظرانداز کتابتیں، معلوم خفیہ ترتیب کی فائلیں اور اصل کھاتوں/سواریوں/رقوم کی معلومات اس میں شامل نہیں۔ فائل نام کی چھان بین مکمل مواد کی خفیہ کلید جانچ نہیں ہے۔
- شناختیں اتفاقی خرابی یا تبدیلی پکڑتی ہیں؛ یہ کسی آزاد دستخط کنندہ کی تصدیق نہیں۔ مقامی نقل اور اس کی شناخت دونوں بدل سکنے والا شخص انہیں جعل سازی سے بدل سکتا ہے۔
- زندہ Functions، قواعد، TTL، علاقہ، خفیہ ترتیبات اور معلوماتی برآمد کی الگ منظور شدہ بنیاد اگلی زندہ تعیناتی سے پہلے درکار ہوگی۔ ابھی اس لیے کوئی زندہ تعیناتی محفوظ قرار نہیں دی گئی۔
- پی ٹو پی/لوکیشن، کرایہ، ایڈمن اور دوسرے درج شدہ کاروباری عیوب ابھی کھلے ہیں۔ مرحلہ صفر کی کامیابی پورے نظام کی تکمیل نہیں۔
- اگلا مجاز قدم صارف کی اجازت کے بعد **صرف مرحلہ اول** ہے۔
